# 次世代3D高校野球 改修仕様
品質目標: MLB The Show 26 相当の操作感・映像表現。素材はオリジナル。既存PWA、育成、セーブ互換性を維持する。
## 既存モジュールへの割当
- src/03c_phys.js: 既存の重力・抗力・マグヌス力を維持。風、地面反発、摩擦、連続衝突判定を追加。打球速度と飛距離を独立に強制しない物理モードを導入。
- src/03b_pitch.js: 球種、回転軸、リリース誤差、疲労、タイミング入力。
- src/08f_ui_3d.js / 08i_ui_gl.js: PBR、影、LOD、描画品質自動調整。
- src/08g_ui_rig.js: GLBスキン、70–100ボーン、足接地IK、両手バット拘束、グラブ拘束。
- src/08h_ui_stadium.js: 土・芝・白線・照明・観客・ベンチ・学校背景。
- src/08k_ui_motion.js / 08l_ui_moves.js / 08n_ui_mocap.js: 投球80、打撃80、守備120、走塁60、待機60、演出100のクリップ制作目標。リリース・接触・捕球イベントを同期。
- src/08m_ui_play.js / 08c_ui_action.js: タッチ・キーボード・ゲームパッド共通入力、ミート位置と時間誤差、強振・通常・ミート、送球精度。
- src/08j_ui_immersion.js: 応援、吹奏楽、実況、土煙、天候、試合前整列、サヨナラ・引退演出。
## 素材仕様
GLB/glTF2、メートル単位、PBR、LOD4段階、KTX2候補。選手身長150–195cm、体型・顔・髪・左右投打・ユニフォームを独立管理。学校10、地方12、都市8、全国3、室内3の球場を目標。素材ID、作者、ライセンス、生成条件をマニフェストに記録。
## 実装順序
1. 既存テストとビルド手順を確認し、試合データ契約を固定。
2. 投手・打者・捕手の縦切り検証環境を構築。
3. 物理と接触判定を試合結果へ接続。旧モードを維持。
4. 守備・走塁・中継AI、リプレイ、カメラ。
5. 球場・観客・音響・大会演出。
6. モデル・モーション量産と端末最適化。
## 合格基準
PC60fps、モバイル30fpsを目標（端末・解像度を記録）。既存セーブ移行、試合完走、左右投打、ボールすり抜け、足滑り、入力遅延、リプレイ再現性をテスト。生成済みindex.html等は直接編集せず、build.shの仕様確認後に再生成する。
本書は設計目標であり、実装済み機能や生成済み素材を示すものではない。
